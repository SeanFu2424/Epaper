## esp32 板卡包安装：第三次错误，找到了本地代理 (Watt Toolkit)

用户第三次报错：


**关键观察**：

### 诊断结果（实证）

  - `ProxyServer=`（空）
  - `AutoConfigURL=`（空）
- `Get-NetTCPConnection -LocalPort 443 -State Listen`：**没返回**

→ 之前所有分析都基于"USB 供电"前提，**漏了一个重要事实**：
- 这块 ESP32-S3-ePaper-1.54 V2 板载 **IP5306 电源管理 IC**
- 长按电源键 = **彻底断电**（不是 USB 拔插）

### 短按电源键后白屏的真因

**短按电源键 ≠ 干净复位**：
- IP5306 输出有 ~100ms 软启动
- ESP32 拿到不稳定电压，启动不完整
- 程序跑到 display.init() 触发了 SSD1681 的 `Clear Display`（上电默认行为）
- 画图步骤可能没跑完，或者 SPI 信号在软启动时错位
- 用户看到：白屏

**插 USB 正常 = LDO 稳压，3.3V 瞬时硬启动，ESP32 复位完整**

### 验证方法（待用户执行）
按 RST 键（不是 BOOT）：
- 按 RST 后 "42.6 km" 出来 → 软启动时序问题（程序没干净复位）
- 按 RST 还是白屏 → SPI / 屏硬件问题

### 治本方向
- 软件：setup() 第一行强制 deep sleep 1s 再醒，让电源稳定
- 硬件：电源键加 RC 延时（不推荐，要动烙铁）
- 接受：V1 翻页固件靠长按 deep sleep 唤醒，短按不用

**新关键信息**：

- delay(2000) 不够 → 软启动时间不止 2 秒

### 第一次修复（delay 2000 → delay 3000 + SPI 4M → 2M + 诊断打印）
仍然白屏（用户 9/10 11:28 反馈 "白屏是完全白屏" + 电池 90%）

### 第二次修复：deep sleep 启动策略（2026-09-10 11:30）
诊断信息：
- 电池 90% → 不是电压问题
- 完全白屏 → SPI 写数据完全没生效
- delay 治标不治本

**根本原因**：
IP5306 软启动 + ESP32 上电时序不匹配。ESP32 拿到电压就开始跑 setup()，但 SSD1681 的 SPI 在电压不稳定时**完全无法通信**，画图阶段（nextPage 触发 full refresh）所有 SPI 数据丢失。

**治本方案**：
- 检测 `esp_reset_reason() == ESP_RST_POWERON`（冷上电）
- 是冷上电 → 先拉低 EPD_PWR → 进 deep sleep 3 秒 → 唤醒后 init
- 不是冷上电（USB 启动 / 软件复位 / RST）→ 直接进 init，不走这个延迟
- 关键点：EPD_PWR 在进 deep sleep **之前**就要拉低（避免 ESP32 唤醒后再次操作 IO）

**代码修改**（`00_HelloScreen.ino` v3）：
```cpp
#include "esp_sleep.h"
#include "esp_system.h"

void setup() {
  Serial.begin(115200);
  delay(100);
  esp_reset_reason_t reason = esp_reset_reason();
  if (reason == ESP_RST_POWERON) {
    pinMode(EPD_PWR, OUTPUT);
    digitalWrite(EPD_PWR, LOW);  // 进 deep sleep 前拉低
    esp_sleep_enable_timer_wakeup(3 * 1000000);
    esp_deep_sleep_start();
    // 不会到这里
  }
  // ... 正常 init
}
```

### 验证步骤（用户重传后）
1. USB 插着上传（ESP_RST_DEEPSLEEP 路径，直接 init）→ 应该出 "42.6 km"
2. 拔 USB，长按电源键 3 秒（ESP_RST_POWERON 路径，走 deep sleep 3 秒）
3. 等 5-10 秒
4. 应该出 "42.6 km"

### 关键原则
- **ESP_RST_POWERON** 是 ESP32 的内部复位原因，跟 USB / RST / 软件复位 都不一样
- **deep sleep 唤醒**也会跑 setup()，但 reset reason 是 ESP_RST_DEEPSLEEP → 跳过延迟
- **用户每次冷开机多等 3 秒**，但彻底解决白屏问题
