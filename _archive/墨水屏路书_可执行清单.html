核心架构决策（先记住这一条）

服务端渲染，设备端只当相框。手机/电脑把整屏画面渲染成 1-bit 位图字节流传给设备，设备只负责"收字节 → 刷屏"。这样中文字体、界面改版全在手机侧完成，固件代码不到 300 行。
反例：在 ESP32 上塞中文字库、写布局代码——改一次界面就要重新烧录，新手会卡死在这里。

MVP 边界：无 GPS、无实时速度。上传 GPX → 生成 N 张卡片位图 → 下发 → 按键翻页。其余全部留给第二版。

阶段一 · 认板子 + 搭环境 2–3 天

拿到快递第一件事：确认主控、屏幕型号、接口，并向店家索要资料包。

已确认硬件：ESP32-S3 + 1.54" 200×200 + 8MB Flash/PSRAM，注意四件事：
① 也没有经典蓝牙——S3 同样只有 BLE（仅 ESP32 经典款有 SPP），网上传图例程用不了；但 V1 走 SD 卡，不需要无线；
② 原生 USB——必须把 USB CDC On Boot 设为 Enabled，否则串口一个字都看不到；
③ PSRAM 选 OPI PSRAM——选错能编译但一跑就崩；deep sleep 唤醒脚是 GPIO0–21（比 C6 宽）；
④ 优先跑厂商 Demo——引脚与驱动类以厂商资料为准，不要猜。

V1 捷径：用 SD 卡槽跳过数据传输。电脑渲染 BMP → 拷进 SD 卡 → 插回板子 → 读取翻页。不用写 USB/BLE/小程序，工作量从几周压到几天。

C/C++ 只需补：指针与数组、struct、位运算、uint8_t 定长类型、PROGMEM。当字典查，不用通读。

阶段二 · 点亮屏幕 3–5 天

搞懂 SPI、分辨率/缓冲区、全刷 vs 局部刷、LUT 四个概念即可。

阶段三 · 把"显示什么"设计对 1 周

最难的不是技术，是"40km/h 手抖状态下 300ms 读完"。一屏只说一件事。

阶段四 · 交互、存储与功耗 3–5 天

目标是脱离电脑、靠电池跑几周。M4 是整个项目的分水岭。

阶段五 · 无线下发 1–2 周

严格按 USB → WiFi → BLE 顺序推进，别一上来啃小程序蓝牙。

阶段六 · GPX 分析自动生成路书 1–2 周

纯软件，与硬件解耦，可并行做，最容易出成就感。
